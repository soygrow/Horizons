# 架构与部署方案：前后端分离 + 用户系统 + 订阅

**文档版本：** V1.1
**状态：** 已评审；S0（monorepo 骨架 + 前后端分离）已完成，S1（用户系统）待实施
**前序文档：** 功能与数据字段以 `docs/2-AI工具榜单页面方案.md` 为准（模仿 columbus.tools，先对齐再差异化）。

---

## 一、背景与目标

当前 Horizons 是「纯前端 Next.js 站点」：数据来自 `content/*.json` 静态导入，无后端、无用户、无付费。

本次升级目标：

1. 接入订阅，因此必须有**用户注册/登录**（先接 Google 登录）→ 引入**后端**。
2. **前后端代码物理分离**，用不同文件夹组织。
3. 数据字段**完全参考哥伦布（columbus.tools）**：先模仿其 9 列表格、付费墙「解锁全部站点」、8 频道导航、详情页高级字段，再找差异化。

一句话结论：把 Horizons 从「静态榜单站」升级为「登录 + 订阅解锁完整数据的 AI 工具情报站」。

## 二、需求总览

### 2.1 功能需求

| 模块 | 需求 | 优先级 |
|------|------|--------|
| 榜单/详情（现状） | 保留 `/`、`/tools`、`/tools/[domain]` 全部现有功能 | P0 |
| 用户系统 | Google OAuth 登录/登出、用户资料、会话保持 | P0 |
| 订阅 | 付费墙：免费看 Top N + 基础字段，订阅解锁全部站点 + 高级字段 | P0 |
| 订阅管理 | 升级/降级/取消、账单门户、续费（webhook 驱动） | P1 |
| 账户页 | `/account`：订阅状态、方案、续费入口 | P1 |
| 付费字段数据 | 流量/来源/地区/关键词/价格历史/全量快照等（对齐哥伦布详情页） | P2 |
| 频道扩展 | AI好公司、AI行业报告、AI出海周刊、AI编程热榜、Changelog | P3（模仿哥伦布） |

### 2.2 非功能需求

- **SEO 不倒退**：免费榜单数据保持 SSG/SSR 预渲染，搜索引擎可见。
- **付费数据不可前端泄露**：高级字段必须后端鉴权下发，不能打进前端 bundle。
- **合规**：Google OAuth 走标准授权码流；支付走 PCI 合规的支付服务商（Stripe/Lemon Squeezy），不自行处理卡号。
- **成本可控**：无自建数据库服务器，全走 Cloudflare 边缘托管（免费额度内）。
- **可回滚**：迁移分阶段，每阶段可独立验证与回退。

## 五、关键技术决策（ADR）

### ADR-1：前后端分离采用 pnpm monorepo

- **决策：** `apps/web` + `apps/api` + `packages/shared`，pnpm workspaces 管理。
- **理由：** 单一仓库、一次提交同时发布前后端；`shared` 包保证前后端类型/字段分级规则一致（付费墙规则不能两端各写一套）。
- **备选：** 两个独立仓库（`horizons-web` + `horizons-api`）。放弃原因：共享类型与字段分级需要跨仓库同步，容易漂移。
- **代价：** 构建脚本略复杂，需按 workspace 分别部署两个 Worker。

### ADR-2：后端运行时 = Cloudflare Workers + Hono + D1 + KV

- **决策：** `apps/api` 用 **Hono** 跑在 Cloudflare Workers，数据用 **D1（SQLite）**，会话/缓存用 **KV**。
- **理由：** 与已选定的 Cloudflare 部署（前端 OpenNext）同生态，无额外服务器；Hono 是 Cloudflare 官方推荐、TS 原生、极轻；D1 对「用户+订阅」这种小数据量、低写入足够且免费额度宽裕。
- **对比：**

| 候选 | 优点 | 缺点 | 结论 |
|------|------|------|------|
| Cloudflare Workers + Hono + D1 | 同生态、无运维、免费额度 | 需适配 edge 限制（无长连接） | ✅ 采用 |
| 独立 Node 服务（Fastify/NestJS）+ VPS | 无 edge 限制、生态成熟 | 违背已定 Cloudflare 路线、需运维 | 备选 |
| Supabase（Auth+DB）自托管 | 用户系统开箱即用 | 引入新平台、非 Cloudflare 生态 | 备选 |

### ADR-3：认证 = Google OAuth 自实现授权码流 + JWT 会话

- **决策：** 自实现 Google OAuth 2.0 **授权码 + PKCE** 流程，签发 **JWT（httpOnly cookie，`SameSite=Lax`, `Secure`）** 作为会话。
- **理由：** 在 Workers 上最可控、无第三方托管用户数据、免费；逻辑简单（一个登录跳转 + 一个回调）。
- **备选：**
  - **Auth.js (NextAuth v5)**：集成快，但跑在 OpenNext/Workers 上适配成本高、坑多。
  - **Clerk**：省事但用户数据托管第三方、按 MAU 收费、有厂商锁定。
- **代价：** 需自己实现 CSRF（state 参数）+ 会话过期/刷新，安全细节自己负责（见第九章）。

### ADR-4：订阅支付 = Stripe（首选） / Lemon Squeezy（备选）

- **决策：** 首选 **Stripe**（Checkout + Customer Portal + Webhook）。
- **理由：** 全球化、文档全、订阅/续费/取消/降级能力完整、webhook 成熟。
- **对比：**

| 维度 | Stripe | Lemon Squeezy |
|------|--------|---------------|
| 税务/合规 | 需自配 Stripe Tax | Merchant of Record，代缴全球税 |
| 复杂度 | 中 | 低 |
| 到账/费用 | 2.9% + 30¢ 起 | 约 5% 起（含 MoR） |
| 集成 | webhook 全 | API 简单，webhook 全 |
| 结论 | ✅ 首选 | 若想省全球税务合规，换它 |

- **决策建议：** 首版若想最快上线、不碰税务 → 用 **Lemon Squeezy**；否则 **Stripe**。此为待确认决策 D3。

### ADR-5：数据服务形态 = 基础数据静态 + 付费字段走 API（渐进）

- **决策：** 基础榜单字段继续 `content/*.json` SSG（免费可见，保 SEO）；**付费/高级字段**放 D1，由 `apps/api` 鉴权下发；前端详情页对订阅用户异步 hydrate 高级字段。
- **理由：** 不推翻已验证的 SSG；付费墙「解锁全部站点」的本质是「免费看 Top N、订阅看全部 + 高级字段」，只需控制字段与条目范围，不必全量数据重构成 API。
- **演进路径（何时全量进 D1）：** 当出现「收藏/自定义榜单/用户提交工具」等需要 user↔tool 关联的功能时，再把工具主表迁入 D1。当前不需要。
- **关键红线：** 任何付费字段**不得**出现在 `apps/web` 的静态产物里；只能通过鉴权 API 返回。

### 6.2 数据库表（D1 / SQLite）

```sql
-- 用户
CREATE TABLE users (
  id            TEXT PRIMARY KEY,        -- nanoid
  google_sub    TEXT UNIQUE NOT NULL,    -- Google 唯一 ID
  email         TEXT NOT NULL,
  name          TEXT,
  avatar_url    TEXT,
  created_at    INTEGER NOT NULL,        -- epoch ms
  updated_at    INTEGER NOT NULL
);

-- 订阅
CREATE TABLE subscriptions (
  id                        TEXT PRIMARY KEY,
  user_id                   TEXT NOT NULL REFERENCES users(id),
  provider                  TEXT NOT NULL,          -- 'stripe' | 'lemonsqueezy'
  provider_customer_id      TEXT,
  provider_subscription_id  TEXT,
  plan_id                   TEXT NOT NULL,          -- 'monthly' | 'yearly' | 'lifetime'
  status                    TEXT NOT NULL,          -- trialing/active/past_due/canceled/incomplete/expired
  current_period_start      INTEGER,
  current_period_end        INTEGER,
  cancel_at_period_end      INTEGER NOT NULL DEFAULT 0,
  created_at                INTEGER NOT NULL,
  updated_at                INTEGER NOT NULL
);

-- 付费字段（仅订阅可见，key 关联 tool）
CREATE TABLE tool_pro_fields (
  tool_id        TEXT PRIMARY KEY,        -- 对应 AITool.id
  traffic        TEXT,                    -- JSON: 访问量/排名
  geo_distribution TEXT,                  -- JSON: 地区分布
  keywords       TEXT,                    -- JSON: 关键词
  price_history  TEXT,                    -- JSON: 价格历史
  screenshots    TEXT,                    -- JSON: 截图列表
  updated_at     INTEGER NOT NULL
);

-- 未来：收藏/自定义榜单
-- CREATE TABLE favorites (user_id, tool_id, created_at);
```

会话采用**无状态 JWT**（不落库），secret 存 Worker Secret；如需强制登出可加 KV 黑名单（可选）。

## 七、用户与订阅流程

### 7.1 登录（Google OAuth 授权码 + PKCE）

```
浏览器                 apps/web             apps/api              Google
  │ 点击"用 Google 登录"  │                     │                     │
  │──────────────────────>│ 生成 state(防CSRF)   │                     │
  │<─ 302 到 Google 授权页─────────────────────────────>│
  │<────────────────────────────────────────────────────── 授权页 │
  │ 授权后 302 带回 code+state                    │                     │
  │──────────────────────>│ /api/auth/google/callback (带 code)    │
  │                       │──────────────────────>│ 用 code 换 token │
  │                       │                       │───────────────────>│
  │                       │                       │<── id_token/userinfo │
  │                       │                       │ upsert users       │
  │                       │<─ 302 回前端 + Set-Cookie: session(JWT) ───│
  │<─ 302 到 /account ───│                       │                     │
```

- 会话 JWT 存 httpOnly cookie，`SameSite=Lax`、`Secure`、`Path=/`。
- `GET /api/me` 返回当前用户 + 订阅状态，前端据此渲染「登录/头像/升级」按钮。

### 7.2 订阅（以 Stripe 为例）

1. 用户点「解锁全部」→ `POST /api/subscriptions/checkout` → 后端创建/复用 Stripe Customer + Checkout Session → 返回 `url`，前端跳转。
2. 支付成功后 Stripe 回调 `success_url`；同时异步发 webhook 到 `/api/webhooks/stripe`（签名校验）。
3. webhook 事件 `checkout.session.completed` / `customer.subscription.updated/deleted` 驱动 `subscriptions` 表写入/更新。
4. 取消/升级走 Stripe Customer Portal（`POST /api/subscriptions/portal`）。

### 7.3 鉴权与付费墙判定

- `apps/api` 中间件解析 JWT → 查 `users` + `subscriptions` → 得到用户 tier（`anon` / `free` / `pro`）。
- 榜单列表：免费用户只返回 Top `FREE_TOOL_LIMIT` 条；`pro` 返回全部。
- 详情页高级字段：`GET /api/tools/:domain/pro` 校验 `pro`，否则 402/403；前端仅在 pro 状态下请求并 hydrate。

## 八、部署方案（Cloudflare）

### 8.1 拓扑

| 资源 | 用途 | 说明 |
|------|------|------|
| Worker `horizons-web` | 前端 Next.js | 经 `@opennextjs/cloudflare` 构建 |
| Worker `horizons-api` | 后端 API | Hono + D1 + KV |
| D1 数据库 | 用户/订阅/付费字段 | `horizons-db` |
| KV Namespace | 会话黑名单/缓存/限流 | `horizons-kv` |
| Route | `horizons.tools/api/*` → api；其余 → web | 同域名路由 |
| Secrets | `SESSION_SECRET`、`GOOGLE_CLIENT_ID`、`GOOGLE_CLIENT_SECRET`、`STRIPE_SECRET_KEY`、`STRIPE_WEBHOOK_SECRET` | `wrangler secret put` |

> 版本确认（已实测）：`@opennextjs/cloudflare@1.20.12` 的 peer 依赖为 `next: >=15.5.28 <16 || >=16.4.1`，当前 `next@16.4.1` **兼容**；需 `wrangler@^4.148.0`。

### 8.2 构建与发布（Git 自动触发）

沿用你 Cloudflare 的「push 即部署」习惯：

- `apps/web` 与 `apps/api` 各自绑定到 Cloudflare，构建命令分别：
  - web：`pnpm --filter web build && pnpm --filter web deploy`（OpenNext 内部调用 wrangler）
  - api：`pnpm --filter api deploy`（Hono → wrangler deploy）
- `main` 推送后由 Cloudflare Git 集成自动构建发布两个 Worker（与 Argus 同机制，只是这里两个 Worker + 一个 D1）。
- 首次需执行一次：`wrangler d1 migrations apply` 建表。

### 8.3 环境变量

| 变量 | 归属 | 来源 |
|------|------|------|
| `GOOGLE_CLIENT_ID/SECRET` | api | Google Cloud Console（OAuth 客户端，回调 `https://horizons.tools/api/auth/google/callback`） |

## 九、安全要点

- OAuth `state` 参数防 CSRF；`code` 一次性使用；校验 `google_sub` 而非仅 email。
- 会话 JWT 签名密钥入 Secret，不入库、不进 git；`Secure` + `SameSite=Lax`。
- Stripe webhook **必须**验签（`STRIPE_WEBHOOK_SECRET`）；webhook 端点幂等处理重复事件。
- 付费字段只在鉴权后返回，绝不出现在 SSG 产物；前端也做 `tier` 判定（仅 UX，最终安全靠后端）。
- 限流：登录/回调/支付端点加 KV 限流，防爆破。
- `content/aitools.json` 若含付费字段，抽离到 D1，避免随前端产物泄露。
