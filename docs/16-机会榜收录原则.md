# 机会榜：收录与评分原则（V2.0 · 一人公司版）

**路由：** `/opportunity`（最新一批）+ `/opportunity/archive`（历史归档）+ `/opportunity/[slug]`（详情）
**导航：** 「机会榜」
**数据形态：** 人工策展汇编 `content/opportunities.json` + 构建期从四个榜单回读证据（`content/dist/opportunity/**`）
**定位：** 不是第五个榜单，而是**四个榜单的交叉结论**——把趋势词、AI 工具、GitHub 仓库、AI 模型四份信号放在一起，回答「一个人、几千块、六周内，现在能站哪个位置」。

---

## 一、这个榜单回答什么

| 用户 | 最需要的信息 |
| --- | --- |
| 独立开发者 / 一人公司 | 我一个人能不能做出来、启动要多少钱、做出来谁自己掏钱买 |
| 副业 / 小团队创业者 | 位置在哪、窗口还有多久、第一批用户从哪个渠道来 |
| 转型者 / 技术型自由职业者 | 用哪些现成开源件和模型、第一周具体干什么 |

**明确不回答：** 融资建议、市场规模预测（TAM/SAM）、"月搜索量"推算、股票与投资标的、需要销售团队和组织采购的生意。

**为什么只收这类机会：** 本站读者是一人公司，钱少、人少、没有销售。一条机会如果必须靠地推、渠道代理、企业采购流程才能卖出去，对读者就是**负资产**——它看起来对，做起来死。所以「能不能一个人卖出去」不是加分项，是**准入否决项**。

**产品差异点：** 别的榜单告诉你「什么在热」；机会榜告诉你「热的这些信号拼在一起，缺口在哪一侧，你一个人第一步敲哪个门，第一笔钱从谁口袋里来」。

## 二、原则 0：一人公司适配（准入否决项，缺一即出局）

这一节先于一切。任何一条不满足，无论综合分多高，都不进榜。

| 检查项 | 硬标准 | 为什么 |
| --- | --- | --- |
| 启动资金 | 首月 ≤ 150 美元，稳定期 ≤ 300 美元/月 | 一人公司没有试错预算，成本结构必须先活下来 |
| 单人交付 | 1 人 ≤ 6 周做出**能收费**的版本 | 超过 6 周的项目，一个人会在中途失去动力与现金流 |
| 获客方式 | 必须是**自分发渠道**：搜索 / 平台内置市场 / 社区 / 开源 / 内容 | 没有销售、没有投放预算，唯一杠杆是渠道自带流量 |
| 付费方 | **自己刷卡的个人或小老板**，不经过采购、不签合同 | 走采购流程就是 3–9 个月回款，一人公司扛不住 |
| 定价 | 自助可完成：≤ 99 美元/月，或一次性 ≤ 199 美元 | 超过 99 美元，个人决策会变成"要商量" |
| 售后 | 不需要驻场、不需要定制交付、不需要 7×24 响应 | 服务型交付会把人锁死，无法做第二版 |

补充判定：

- **付费方是「公司」不等于对**。判断标准是「谁刷卡」：小店主自己刷卡 → 可以；需要 IT 部门审批 → 出局。
- **能被平台一次更新杀死的机会要明确写出**（例如完全依附单一平台的插件），并在详情页写明对冲方式。
- 优先收录「海外已验证、中文场景空白」的位置：不需要教育市场，只需要换语言与本地合规。

## 三、五条内容原则

### 原则 1：跨榜交叉 ≥ 3 源

每条机会必须引用**至少 3 个不同榜单**的证据（趋势词 / AI 工具 / GitHub / AI 模型），且其中**至少 1 个趋势词**。

- 单一榜单的热度不构成机会：趋势词热不代表能变现，工具流量大不代表还有空间。
- 交叉的作用是让「需求侧（趋势词 + 工具流量）」与「供给侧（GitHub 仓库 + 模型能力与价格）」同时出现，缺口才可判断。

### 原则 2：证据可追溯、可点击

每条证据写成 `{ board, ref, note }`，`ref` 是榜单主键（趋势词 slug / 工具 domain / 仓库 fullName / 模型 slug）。

- 构建期**逐个回查**：`ref` 在对应榜单不存在 → 构建直接失败，不允许上线。
- 具体数字（访问量、星数、价格、机会分）**由构建期从榜单实时注入**，人工写的 `note` 里不允许出现会被数据更新打脸的硬数字。
- 详情页每条证据可点回原榜单条目，形成证据链闭环。

### 原则 3：可执行性优先于热度

`可执行性 F` 权重 20%，同时是**准入门槛**：`F < 60` 的机会不进榜，无论热度多高。

判分依据：
- 现有开源件 / 模型 API 能承担 60% 以上的基础工作量；
- 不需要自建模型、不需要自建基础设施、不需要独家数据；
- 核心难点是「编排 + 交互 + 领域判断」，不是「训练」或「BD」。

### 原则 4：供给缺口是核心判据

`供给缺口 G` 权重 25%，是五个分项里最能区分"真机会"与"红海"的一项。

- 只有当**需求侧信号强于供给侧信号**时才给高分。
- 对一人公司最有效的三种缺口形态：
  1. **价格缺口**：现有产品按席位卖给企业（$30/席起），个人用户被价格挡住；
  2. **语言/本地化缺口**：海外产品已验证需求，中文场景无人做，或中文质量明显差；
  3. **形态缺口**：现有产品是「通用工具」，缺少针对单一高频场景的完整闭环（输入 → 产出 → 可直接交付）。
- 已有强对手正面占位的方向，只在**切入口径明显不同**时收录，并在详情页明确写出「不要正面做什么」。

### 原则 5：写下失效条件，不下无边界结论

每条机会必须包含：
- `risks[]`：至少 2 条风险 + 应对方式；
- 每个实施阶段的 `gate`：通过标准，达不到就停；
- `outcome.reality`：明确写出这些数字**不成立的条件**。

禁止出现「潜力巨大」「前景广阔」「千亿市场」这类无法证伪的表述。

## 四、评分模型

```
机会综合分 O = 0.30 × D 需求证据
             + 0.25 × G 供给缺口
             + 0.20 × F 可执行性
             + 0.15 × T 时机窗口
             + 0.10 × M 自助变现
```

| 分项 | 权重 | 测什么 | 判定口径（一人公司视角） |
| --- | --- | --- | --- |
| `D` 需求证据 | 30% | 是否有人在**主动搜索**、在付费 | 引用的趋势词机会分均值；搜索意图是"找工具"而非"看新闻" |
| `G` 供给缺口 | 25% | 现有供给是否已填满个人市场 | 同赛道工具是否只做企业版、中文是否空白、头部是否增长停滞 |
| `F` 可执行性 | 20% | 一个人多久能做出收费版 | 开源件覆盖度、模型 API 成本、单人周数（≤ 6 周） |
| `T` 时机窗口 | 15% | 现在做还来不来得及 | 趋势词阶段、模型价格下降带来的成本结构变化 |
| `M` 自助变现 | 10% | 谁掏钱、能不能不问人就买 | 是否有同类产品已验证自助付费；单价是否 ≤ 99 美元/月 |

**等级：** S ≥ 80 ／ A ≥ 72 ／ B ≥ 64 ／ C < 64。名次按综合分降序，同分比 `G` 再比 `D`。

### 防漂移闸门（构建期硬校验）

机器不做主观打分，只做三件事：**取数、校验、渲染**。

1. `D` 分与所引用趋势词的平均机会分偏差 **> 20 分** → 构建失败（防止人工拍分脱离数据）。
2. 引用榜单数 < 3 或缺少趋势词证据 → 构建失败。
3. 任一 `ref` 在榜单中找不到 → 构建失败。
4. `F < 60`、`M < 50`、风险少于 2 条、`solo.weeks > 6`、缺 `firstWeek` → 构建失败。

> 榜单数据变化后，如果某条机会的需求证据不再成立，构建会中断，逼着人重写或下架，而不是让一条过期结论继续挂着。

## 五、页面必须回答的六个问题

一条机会如果在页面上说不清这六件事，就是没写完。

| # | 用户心里的问题 | 页面对应字段 |
| --- | --- | --- |
| 1 | 这到底是个什么生意？ | `title` + `oneLiner` |
| 2 | 为什么现在有位置？ | `thesis.where` + `thesis.whyNow` + 四榜证据 |
| 3 | 我一个人做得出来吗？ | `solo.budget` / `solo.weeks` / `solo.channels` + `build.mvpScope` |
| 4 | 第一周我具体干什么？ | `firstWeek[]`（三条，写到可执行的动作） |
| 5 | 谁掏钱、怎么收？ | `money.price` / `money.payer` / `money.first10` |
| 6 | 什么情况下这事不成立？ | `risks[]` + `outcome.reality` |

### 5.1 列表页

| 字段 | 用户看到什么 |
| --- | --- |
| 名次 + 等级 | `01` + S/A/B |
| 机会标题 + 一句话 | 要做什么、缺口在哪一侧 |
| **一人公司标签组** | `1 人` / `4 周` / `≤ 150 美元/月` / `搜索获客` —— 一眼判断"这是不是我的活" |
| 综合分 + 五维条 | 凭什么排在这 |
| 证据徽标 | 趋势/工具/开源/模型 各几条、跨几榜 |
| 切入形式 + 窗口期 | 产品、开源、内容、服务；多久内有效 |

### 5.2 详情页

| 区块 | 内容 |
| --- | --- |
| Hero | 标题、一句话、五维分、等级、名次、窗口、适合谁、**第一周第一件事** |
| 指标条 | 综合分、五维分、证据数、跨榜数 |
| 01 机会在哪里 | 缺口、为什么是现在、**不要做什么** |
| 02 四榜证据 | 按榜单分组，主键 + 实时数值 + 判断 + 回链 |
| 03 一个人怎么做 | 产品形态、MVP 范围、可直接复用的开源件与模型、技术栈 |
| 04 第一周清单 | 三条可执行动作（当天就能开始） |
| 05 实施路径 | 阶段 → 周期 → 动作 → 交付物 → 通过标准 |
| 06 钱怎么来 | 定价、谁刷卡、**前 10 个付费用户从哪来**、天花板、现实边界 |
| 07 风险与失效条件 | 风险 + 应对 |
| 右侧栏 | 分项依据、一人公司适配表、证据来源、原则摘要、上下一条 |

## 六、更新与淘汰

- **更新频率：** 每周复核一次；引用条目数据由构建自动刷新，人工只需复核 `note` 与分数。
- **淘汰触发（任一命中即下架或改判）：**
  1. 引用的趋势词跌入 `cooling` 且机会分下降 ≥ 15；
  2. 赛道出现融资充足的同口径正面竞争者，且已覆盖个人版；
  3. 产品开始需要销售、渠道或定制交付才能增长（违反原则 0）；
  4. 阶段 `gate` 连续两次未通过；
  5. 构建期闸门连续报错且无法在当周修正。
- **数量约束：** 每批固定 5 条，构建期校验（`batch` 缺失或某批不等于 5 条即中断）。批内强制排序，不做"什么都能进"的堆积。
- **频率：** 每周一批（`batch` 用 ISO 周，如 `2026-W44`）。不做日更——机会窗口是 6–12 个月的慢变量，日更只能靠降低标准凑数。
- **新旧分工：** `/opportunity` 只渲染最新一批；更早批次进 `/opportunity/archive` 归档，详情页对历史批次打「历史批次」标记。窗口过期的机会仍在归档可读，但不占最新版面。

## 七、「我在做」：参与标记与留言

机会的价值最终要靠有人真的去做来验证，所以详情页允许读者公开标记「我在做」。它不是点赞，是带时间线的行动记录。

- **一人一条参与记录**：`opportunity_doers` 表对 `(slug, user_id)` 建唯一索引，重复点击 = 更新进展，不会重复占位。
- **留言可多条**：`opportunity_updates` 不限条数，只按时间倒序展示，保留"第 3 周做出收费版 → 第 6 周被证伪"这类完整过程。
- **进展状态**：`在做 / 已上线 / 暂停了 / 放弃了`，四种状态都允许公开发布。允许公开"放弃"是刻意的——失败样本比成功故事更能说明机会是否成立。
- **公开范围**：只展示头像 + 昵称 + 留言 + 状态，不含邮箱；接口按 slug 与 userId 分页读取，单机会最多返回 60 人。
- **写入门槛**：必须 Google 登录；内容去标签、压空白、上限 280 字；同一用户 20 秒内只能提交一次；可随时退出并一并删除自己的留言。
- **审核口径**：留言是用户内容，不是榜单结论。出现广告、辱骂、引流二维码等，直接删除并保留拉黑名单（当前为人工处理）。

接口（`apps/api`，路由 `horizons.tools/api/*`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/opportunity/doing/counts?slugs=a,b` | 列表页角标：批量人数（最多 20 条） |
| GET | `/api/opportunity/:slug/doing` | 参与名单（含当前登录用户的 me） |
| GET | `/api/opportunity/:slug/doing/:userId` | 某人的全部留言 |
| POST | `/api/opportunity/:slug/doing` | 加入或更新进展（需登录） |
| DELETE | `/api/opportunity/:slug/doing` | 退出，并删除自己的留言 |

数据表见 `apps/api/migrations/0002_opportunity_doing.sql`；上线前需 `wrangler d1 migrations apply horizons-db --remote`。

## 八、免责与口径

- 所有分数是基于公开信号的**相对排序**，不是成功率预测，也不承诺任何人能赚到钱。
- 榜单只做方向判断与路径拆解，不构成任何投资、法律或商业承诺。
- 引用条目数值来自各榜单采集快照，可能滞后于真实世界；快照时间在页面标注。
