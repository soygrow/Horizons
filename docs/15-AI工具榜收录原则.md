# AI 工具榜收录原则（tps-rank-v1）

> 本文件是所有采集脚本、审核与手动补录的唯一判定标准。
> 判定顺序：**准入 → 分层 → 排序**。任何一站先过准入，再过分层，最后才有名次。
> 修改本文件必须同时升级版本号，并说明变更理由。

## 一、为什么要先定原则

没有门槛的榜单会出现三类问题，且都已在历史数据中发生过：

| 问题 | 实例 | 后果 |
| --- | --- | --- |
| 把大厂主站当工具收进来 | `microsoft.com`（6447 万访问）、`cloudflare.com`（6347 万） | 榜单变成大厂流量榜，用户找不到真正的新工具 |
| 收进已沉寂的站 | PH 首发后零流量、零更新的站 | 用户点进去是死产品，损害榜单信任 |
| 数据缺失被当成没流量 | `claude.com` 曾排 118 名 | 排序失去可解释性 |

## 二、准入（有任一条不满足即不进榜）

### A1 对象必须是「独立的 AI 产品」

- 有独立产品官网（独立域名或独立子站），不是纯内容页、目录页、文档页
- 主营或核心卖点是 AI 能力（生成式、模型、Agent、AI 增强的工作流）
- 不是聚合导航站（`theresanaiforthat.com` 一类）、不是模型榜单站、不是资讯站

### A2 排除平台型大厂主站

以下域名属于「平台/基础设施」，不是受众要找的「AI 工具」，不参与排名：

```
microsoft.com  google.com  apple.com  amazon.com  cloudflare.com
figma.com  adobe.com  notion.so  slack.com  zoom.us
```

> AI 原生产品保留（如 `claude.com`、`meta.ai`、`kling.ai`），它们是受众真正会主动搜索的目标。
> 该名单随数据增长人工维护，新增前需确认「普通用户是否会把它当作一个可试用的 AI 工具」。

### A3 站点必须可用

- 域名可正常访问（HTTP 200，非停放页、非「建设中」、非 404）
- 不是纯 App Store / Chrome 商店的跳转壳

### A4 必须有可验证的真实规模（三选一）

| 路径 | 判定 |
| --- | --- |
| 有月访问量数据 | 月访问量 **≥ 1,000** |
| 无月访问量但有自然搜索流量 | 自然搜索流量 **≥ 300** |
| 两者都无 | Product Hunt 票数 **≥ 300 且发布 ≤ 120 天**（新星豁免，仅进观察区） |

**无任何规模信号且不满足新星豁免的站，不进榜。** 这是当前 43 个「完全无数据」站的处理依据。

## 三、分层（决定展示位置，不决定是否存在）

| 层级 | 条件 | 展示 |
| --- | --- | --- |
| **主榜 Core** | 月访问 ≥ 10,000，或（1,000–10,000 且环比 ≥ 0） | 参与综合得分排名，显示 `#` 名次 |
| **观察区 Watch** | 月访问 1,000–10,000 且环比 < 0；或仅满足 A4 新星豁免 | 单独分区，标「待验证」，**不占主榜名次** |
| **不收录** | 不满足 A4 | 从数据集中移除，或保留在候选池不参与构建 |

判定树：

```
有月访问量?
├─ 是 → ≥10000 ? 主榜
│        └ 否 → 1000~10000?
│                ├─ 环比 ≥0 → 主榜
│                └─ 环比 <0 → 观察区
└─ 否 → 有自然搜索流量?
         ├─ ≥300 → 观察区
         └─ <300 或无 → PH≥300 且 ≤120 天?
                          ├─ 是 → 观察区
                          └─ 否 → 不收录
```

## 四、排序（tps-rank-v1）

主榜内部按综合得分降序，模型见 `packages/shared/src/tool-score.ts`：

| 维度 | 权重 | 说明 |
| --- | --- | --- |
| 用户规模 | 30 | 月访问量对数归一，10 万记满分 |
| 增长动能 | 20 | 环比增长，0% 记 50 分 |
| 搜索健康 | 15 | 自然搜索占比，40% 记满分 |
| 外部热度 | 15 | PH 票数 / GitHub 星 |
| 域名权重 | 10 | DR |
| 机会评分 | 10 | 大模型 `opportunity.score` |

**口径纪律**：`monthlyVisits` 只取 SimilarWeb 口径，**不允许**用自然搜索流量折算替代。
搜索流量与总访问量差 3–5 倍，混用会让排序不可解释。缺失时该维度按剩余权重归一（现有实现）。

## 五、采集纪律（控制成本）

1. **先查缓存再调用**：所有付费请求走 `scripts/fetch/api-cache.ts`，同一 (provider, endpoint, key) 在 TTL 内不重复计费。
2. **先免费筛，后付费采**：候选先过 A1–A3（纯 HTTP 检查，0 成本），再花 SimilarWeb 额度。
3. **无数据不缓存为定论**：免费源的超时/抖动不写入缓存（`cacheNull:false`），避免误判被固化。
4. **更新频率**：SimilarWeb 数据 TTL 30 天，DR 90 天；整榜更新建议 15–30 天一次。

## 六、数据字段口径

| 字段 | 来源 | 缺失时 |
| --- | --- | --- |
| `trafficMetrics.monthlyVisits` | SimilarWeb（Apify lergassy） | 不推算，保持缺失 |
| `metrics.organicVisits` | 优先 SimilarWeb 自然搜索 | 缺失不填 0 |
| `metrics.domainWeight` | Ahrefs DR（Apify） | 缺失不填 0 |
| `phUpvotes` | Product Hunt 免费 API | — |
| `opportunity.score` | 大模型分析 | 缺失则该维度权重剔除 |
