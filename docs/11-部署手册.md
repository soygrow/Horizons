# 部署手册（Cloudflare Workers）

**一句话：`pnpm deploy`。**

```bash
pnpm deploy          # 构建并部署 web + api（默认）
pnpm deploy web      # 只发前端
pnpm deploy api      # 只发后端
pnpm deploy --dry    # 只构建 + 类型检查，不上传（发布前自检）
```

---

## 一、真实机制（重要）

**本项目没有 Cloudflare Git 自动部署。`git push` 不会上线。**

| 事实 | 证据 |
|------|------|
| 线上 `horizons-web` 最后部署于 2026-10-21 09:05 | `wrangler deployments list` 显示 Source 为 `Upload`（本地上传），不是 Git/Builds |
| 仓库内无 CI | 无 `.github/` 目录，Cloudflare 侧也未接入 Git 集成 |
| 因此 10-27 / 10-28 的推送都没有上线 | 线上首页导航仍无「GitHub榜」，`/github` 返回 404 |

> 旧文档 `docs/3-架构与部署方案.md` §8.2 曾写「push 即部署」，与事实不符，已更正。

**部署 = 本地用 wrangler 构建并上传。** 所有操作收敛到 `scripts/deploy.sh`，不要手工散跑 `wrangler deploy` / `opennextjs-cloudflare`，否则容易漏建或漏发某个 Worker。

## 二、拓扑

| 资源 | Worker 名 | 入口 | 域名路由 |
|------|-----------|------|----------|
| 前端 | `horizons-web` | `apps/web/wrangler.jsonc`（`.open-next/worker.js`） | `horizons.tools/*` |
| 后端 | `horizons-api` | `apps/api/wrangler.jsonc`（`src/index.ts`） | `horizons.tools/api/*` |
| 数据库 | D1 `horizons-db` | `apps/api/migrations` | — |

两者都在同一个 Cloudflare 账号下，`pnpm deploy` 会依次发布。

## 三、前置条件

1. **wrangler 已登录**（每个新机器只需一次）：
   ```bash
   pnpm --filter @horizons/web exec wrangler login
   ```
   凭据存在 `~/Library/Preferences/.wrangler/default.toml`。换机器/清缓存后会失效，表现为部署报 401 或 `Not logged in`。
2. Node / pnpm 版本按 `package.json` 的 `packageManager`（pnpm 10）。
3. 数据文件存在：`content/github.json`、`content/aitools.json`（脚本会检查）。

## 四、标准发布流程

```bash
# 1. 提交代码（先让 git 干净，避免线上版本无法对应某个 commit）
git add -A && git commit -m "..." && git push origin main

# 2. 自检：只构建不上传，确认类型检查和 OpenNext 构建都过
pnpm deploy --dry

# 3. 正式部署（自动构建 + 上传 + 线上验收 3 个页面）
pnpm deploy
```

脚本结束时会打印：

```
✓ / → 200
✓ /tools → 200
✓ /github → 200
✓ 部署完成，用时 245s
```

任一页面非 200 会以退出码 1 失败，提醒你去看 `wrangler deployments list`。

## 五、验收线上是否真的更新了

`/github` 返回 200 只是必要条件，还要看内容是否为新版：

```bash
# 线上首页导航是否已出现「GitHub榜」
curl -s https://horizons.tools | grep -c "GitHub榜"

# 榜单条数（应为当期入榜数，如 500）
curl -s https://horizons.tools/github | grep -oE "共 [0-9]+ 个可开发项目"
```

## 六、回滚

```bash
# 查看历史版本
pnpm --filter @horizons/web exec wrangler deployments list

# 回滚到某个版本 ID
pnpm --filter @horizons/web exec wrangler rollback <version-id>
```

后端同理，把 `@horizons/web` 换成 `@horizons/api`。

## 七、数据库迁移

只在 `apps/api/migrations` 有新增时执行：

```bash
pnpm deploy api --migrate
```

## 八、常见坑

| 现象 | 原因 / 处理 |
|------|------------|
| push 之后线上没变 | 正常——没有 Git 自动部署，必须 `pnpm deploy` |
| `next build` 因 i18n 类型检查失败 | 给 `src/lib/i18n/zh.ts` 加了 key 却没补 `en.ts`。`DictPartial` 会强制英文键对齐，补齐即可（2026-10-29 就因此卡过一次） |
| OpenNext 构建报 Next 版本不兼容 | `@opennextjs/cloudflare@1.20.12` 要求 `next >=16.4.1`，升级 next 时同步确认 |
| 部署成功但页面 404 | 检查 `apps/web/wrangler.jsonc` 的 `routes` 是否仍为 `horizons.tools/*`，以及访问的是否为主域名（无 www） |
| `wrangler whoami` 报未登录 | 重新 `wrangler login`；脚本第一步就会拦下 |
