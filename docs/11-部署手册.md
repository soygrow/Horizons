# 部署手册（Cloudflare Workers）

**一句话：`pnpm deploy`。**

```bash
pnpm deploy          # 构建并部署 site + api（默认）
pnpm deploy site     # 只发前端（Astro 静态站）
pnpm deploy api      # 只发后端
pnpm deploy web      # 只发旧 Next 站（回滚备胎，无域名路由）
pnpm deploy --dry    # 只构建 + 类型检查，不上传（发布前自检）
```

---

## 一、真实机制（重要）

**本项目没有 Cloudflare Git 自动部署。`git push` 不会上线。**

| 事实 | 证据 |
|------|------|
| 部署来源是 `Upload`（本地上传），不是 Git/Builds | `wrangler deployments list` |
| 仓库内无 CI | 无 `.github/` 目录，Cloudflare 侧也未接入 Git 集成 |
| 2026-10-27 / 10-28 的推送都没有上线 | 当时线上首页导航仍无「GitHub榜」，`/github` 返回 404 |

> 旧文档 `docs/3-架构与部署方案.md` §8.2 曾写「push 即部署」，与事实不符，已更正。

**部署 = 本地用 wrangler 构建并上传。** 所有操作收敛到 `scripts/deploy.sh`，不要手工散跑 `wrangler deploy` / `opennextjs-cloudflare`，否则容易漏建或漏发某个 Worker。

## 二、拓扑（2026-10-29 起）

| 资源 | Worker 名 | 代码 | 入口 | 域名路由 |
|------|-----------|------|------|----------|
| 前端（正式） | `horizons-site` | `apps/site`（Astro 静态站） | `apps/site/wrangler.jsonc`（`./dist` 静态资产） | `horizons.tools/*` |
| 前端（回滚备胎） | `horizons-web` | `apps/web`（旧 Next + OpenNext） | `.open-next/worker.js` | 无（路由已移交） |
| 后端 | `horizons-api` | `apps/api`（Hono） | `apps/api/wrangler.jsonc`（`src/index.ts`） | `horizons.tools/api/*` |
| 数据库 | D1 `horizons-db` | `apps/api/migrations` | — | — |

三者都在同一个 Cloudflare 账号下，`pnpm deploy` 会依次发布 `site` 与 `api`。

## 三、前置条件

1. **wrangler 已登录**（每个新机器只需一次）：
   ```bash
   pnpm --filter @horizons/site exec wrangler login
   ```
   凭据存在 `~/Library/Preferences/.wrangler/`。换机器/清缓存后会失效，表现为部署报 401 或 `Not logged in`。
2. **依赖已安装**：仓库根执行 `pnpm install`（`apps/site` 自 2026-10-29 起也由 pnpm 管理，不再有 `package-lock.json`）。
3. 数据文件存在：`content/github.json`、`content/aitools.json`（脚本会检查）。

## 四、标准发布流程

```bash
# 1. 提交代码（先让 git 干净，避免线上版本无法对应某个 commit）
git add -A && git commit -m "..." && git push origin main

# 2. 自检：只构建不上传
pnpm deploy --dry

# 3. 正式部署（生成 content/dist → Astro 构建 → wrangler 上传 → 线上验收）
pnpm deploy
```

脚本结束时会打印：

```
✓ / → 200
✓ /tools → 200
✓ /github → 200
✓ /trends → 200
✓ /deploy-check-should-not-exist → 自定义 404 页
✓ 部署完成，用时 120s
```

任一检查不通过会以退出码 1 失败，提示去看 `wrangler deployments list`。

`content/dist/**` 是 `content/*.json` 的派生产物（由 `scripts/build/artifacts.ts` 生成），不入库，`pnpm deploy site` 会自动重算。

## 五、验收线上是否真的更新了

状态码 200 只是必要条件，还要看内容：

```bash
# 首页导航是否为新版三频道（AI工具榜 / GitHub榜 / AI趋势词榜单）
curl -s https://horizons.tools | grep -o "GitHub榜"

# GitHub 榜收录条数（应为当期入榜数，如 500）
curl -s https://horizons.tools/github | grep -oE "共 [0-9]+ 个可开发项目"

# 自定义 404 页是否生效（应有页面内容，而非空响应体）
curl -s -o /dev/null -w '%{http_code}\n' https://horizons.tools/deploy-check-should-not-exist
```

> `*.workers.dev` 域名在部分网络（如本机 ISP）会被 reset，本机无法直接访问 `horizons-site.*.workers.dev`。验收请走主域，或用 `pnpm --filter @horizons/site exec wrangler dev` 本地核对。

## 六、回滚

**新站出问题，退回旧 Next 站**（几分钟）：

1. 把 `apps/site/wrangler.jsonc` 的 `routes` 注释掉；
2. 把 `apps/web/wrangler.jsonc` 的 `routes` 恢复为 `horizons.tools/*`；
3. `pnpm deploy web`（会把路由重新绑回 `horizons-web`）。

**同一 Worker 回滚到上一版本**：

```bash
pnpm --filter @horizons/site exec wrangler deployments list
pnpm --filter @horizons/site exec wrangler rollback <version-id>
```

后端同理，把 `@horizons/site` 换成 `@horizons/api`。

## 七、数据库迁移

只在 `apps/api/migrations` 有新增时执行：

```bash
pnpm deploy api --migrate
```

## 八、常见坑

| 现象 | 原因 / 处理 |
|------|------------|
| push 之后线上没变 | 正常——没有 Git 自动部署，必须 `pnpm deploy` |
| `astro build` 报 `Missing field tsconfigPaths on BindingViteResolvePluginConfig.resolveOptions` | astro 升到 6.5+/vite 8（rolldown）后与 `@tailwindcss/vite` 不兼容。已在 `apps/site/package.json` 固定 `astro@6.4.4`、根 `package.json` 加 `pnpm.overrides.vite=7.3.7`，勿随意升级 |
| `astro build` 报 `ERR_PACKAGE_PATH_NOT_EXPORTED: entities/escape` | `apps/site/node_modules` 与锁文件不一致（`parse5` 需要 `entities@^6`）。删掉 `apps/site/node_modules` 后根目录 `pnpm install` |
| 部署报 `Not logged in` / token 刷新失败 | 多为瞬时网络问题，先 `wrangler whoami` 重试；仍失败再 `wrangler login` |
| 部署成功但页面 404 | 检查 `apps/site/wrangler.jsonc` 的 `routes` 是否为 `horizons.tools/*`，以及访问的是否为主域名（无 www） |
| 自定义 404 不生效 | `not_found_handling` 必须是 `404-page`，且构建产物根目录要有 `404.html`（来自 `apps/site/src/pages/404.astro`） |
| 旧 Next 站 `next build` 因 i18n 类型检查失败 | 给 `apps/web/src/lib/i18n/zh.ts` 加了 key 却没补 `en.ts`；`DictPartial` 会强制英文键对齐 |
| OpenNext 构建报 Next 版本不兼容 | `@opennextjs/cloudflare@1.20.12` 要求 `next >=16.4.1` |
