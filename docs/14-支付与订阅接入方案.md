# 支付与订阅接入方案

> 定价：月付 ¥19 / 年付 ¥99（页面已上线：`apps/site/src/pages/pricing.astro`，线上站点为 Astro 的 `apps/site`，`apps/web` 为旧 Next 站，不再部署）。
> 本文回答三个问题：走哪个通道、后端怎么改、按什么顺序做。

---

## 一、结论先行

**推荐路径：一次性支付 + 极简权益模型，分三阶段推进。**

| 阶段 | 触发条件 | 收款方式 | 工作量 |
|---|---|---|---|
| 阶段一 | 现在 | 微信/支付宝个人收款 + 后台手动开通 Pro | 0.5 天 |
| 阶段二 | 有 20+ 付费用户 或 月流水 > ¥3000 | 注册个体工商户 → 支付宝电脑网站支付（+ 微信 Native） | 3~5 天 |
| 阶段三 | 有海外用户实际付费 | 接 MoR（Lemon Squeezy / Paddle）收国际卡 | 2~3 天 |

三条关键判断：

1. **不做自动续费订阅，全部走一次性支付。** 年付 ¥99 相当于 5.2 个月的月付价格，年付必然是绝对主力（预计占 85%+），月付只是价格锚点。用户一年才回来一次，订阅系统的复杂度（扣款失败重试、dunning、取消挽留、退款对账）完全不值得。有效期字段 + 手动续费即可，这也是参考站「通行证」的底层逻辑。
2. **不要为了收 ¥99 去付 5% 的 MoR 抽成。** 你的用户 90% 是中文用户，支付宝/微信覆盖率远高于国际卡。MoR 只在海外订单真的出现后再接。
3. **先人工，再自动化。** 前 20 单人工开通总成本约 1 小时，比提前两周去跑支付签约划算得多；而且这 20 单会告诉你真实的转化率和退款诉求。

## 二、通道选型对比

费率以各平台官网最新公示为准，此处为量级参考。

| 通道 | 主体要求 | 费率量级 | 结算 | 适合 |
|---|---|---|---|---|
| 个人收款码 + 人工开通 | 无 | 0.1%（提现免费） | 实时 | 阶段一验证 |
| 支付宝「电脑网站支付」 | 个体工商户/企业 + **网站需 ICP 备案** | 0.6% | T+1 | 阶段二主力 |
| 微信「Native 支付」 | 同上 | 0.6% | T+1 | 阶段二补充 |
| 聚合支付（虎皮椒/易支付等） | 个人可开 | 1%~3% | T+1 | 想跳过个体户，但有合规与跑路风险 |
| Stripe 直连 | 境外主体 + 境外银行账户 | 2.9% + $0.30，国际卡 +1.5% | 7 天滚动 | 有香港/新加坡公司后 |
| Lemon Squeezy / Paddle（MoR） | 个人/公司可申请，需审核 | 5% + $0.50 | 月结 | 国际卡，代扣 VAT/GST |
| Dodo / Creem / Polar 等新兴 MoR | 个人可申请 | 4%~5% | 月结 | 同上，审核更宽松 |

**排除项：**

- 不要用「个人收款码 + 自动回调」的野路子。个人收款码没有可靠回调，靠截图核对会出错单、被投诉，且违反平台规则。
- 不要一上来就 Stripe。境外主体（香港公司年维护约 ¥6000~10000）+ 记账报税 + 提现汇损，对这个客单价是负收益。

## 三、阶段一：零资质验证（现在就能做）

**目标：验证付费意愿，同时不阻塞产品开发。**

流程：

1. 定价页 CTA 现在指向 `/account`（登录）——保持不变。
2. 加一块「内测申请」入口：登录用户点击后落一条记录到 D1（`pro_requests` 表），你收到通知。
3. 用户同意付费 → 你发个人收款码（或对公账户）→ 收到款后在后台上传开通。
4. 后台用一个受 `ADMIN_TOKEN` 保护的接口开通，不需要任何第三方 SDK。

```http
POST /api/admin/grant
Authorization: Bearer <ADMIN_TOKEN>
Content-Type: application/json

{ "email": "user@example.com", "plan": "year", "note": "微信转账 2026-10-30" }
```

价值：这一步能把「多少人真的会掏 ¥99」这个问题在两周内回答掉，而不是三个月后接完支付才发现没人买。

风险控制：单笔金额小、笔数少时，手动开通的错误率可接受；一旦超过 50 笔就必须进阶段二。

## 四、阶段二：支付宝 + 微信自动收款

### 4.1 前置条件（这是真正的门槛，不是技术）

- 注册**个体工商户**（线上可办，成本数百元，1~2 周下证），经营范围含「信息技术服务」或「软件开发」。
- 网站完成 **ICP 备案**（支付宝/微信商户签约几乎都会核验备案主体与网站内容一致性）。这是最容易被忽略、也最耗时的一环，建议现在就启动。
- 支付宝开放平台创建「电脑网站支付」应用，微信商户平台开通「Native 支付」。

### 4.2 技术方案

复用现有 `apps/api`（Hono on Workers）与 D1，新增 `billing` 路由。

```
apps/api/
├── migrations/
│   └── 0002_billing.sql
└── src/
    ├── routes/billing.ts        # 下单 / 回调 / 查询
    └── lib/
        ├── alipay.ts            # 签名、验签、下单参数（RSA2）
        └── wechat.ts            # v3 签名、解密回调
```

接口设计：

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/api/billing/orders` | 创建订单，返回 `orderId` + 支付宝表单 / 微信二维码 URL |
| `POST` | `/api/billing/webhook/alipay` | 异步通知，验签 → 幂等 → 开通 |
| `POST` | `/api/billing/webhook/wechat` | 同上（需解密 `resource` 字段） |
| `GET` | `/api/billing/me` | 返回当前用户 `plan` / `proUntil` / 历史订单 |
| `POST` | `/api/billing/refund` | 管理员专用，退款并回收权益 |

Workers 环境注意点：

- **不能用 Node 的 `crypto` 同步 API**，支付宝 RSA2 验签要用 `crypto.subtle.importKey` + `verify`（异步），或引入纯 JS 的 `jsrsasign`。
- 微信 v3 回调必须验 `Wechatpay-Signature` 与 `Wechatpay-Timestamp`（5 分钟内有效），并用 APIv3 密钥 AES-GCM 解密。
- 回调必须**幂等**：以 `provider_order_id` 唯一索引 + 事务内 `INSERT OR IGNORE` 判重，重复回调直接返回成功，避免重复加时长。
- 回调**不要信任** `status` 之外的金额字段：金额以自己订单表快照为准，回调只做「这笔订单已付」的确认。

### 4.3 前端

- 定价页 CTA：已登录 → `POST /api/billing/orders` → 支付宝跳转 / 微信展示二维码（`qrcode` 生成，纯前端渲染）。
- 支付返回 `/account?paid=1`，轮询 `GET /api/billing/me` 直到 `proUntil` 更新（最多 60 秒），避免「付了但页面没变」的焦虑。
- 微信扫码需要单独一个「扫码支付」中间页，不要在弹窗里塞二维码。

## 五、阶段三：国际卡（海外订单出现后再做）

推荐 **Lemon Squeezy 或 Paddle**（MoR 模式，平台作为销售方代扣 VAT/GST，无需自行处理境外税务）。两者都以订阅为主，但都支持一次性产品（Pay-what-you-want / single payment product）。

实施要点：

- 同一个 `orders` 表，`provider` 字段区分 `lemonsqueezy` / `paddle`。
- 通过 `custom_data` / `passthrough` 把内部 `orderId` 或 `user_id` 带过去，回调里取回。
- Webhook 验签用平台签名头（LS 为 `X-Signature` HMAC-SHA256）。
- 定价用平台后台配置，前端加 `/pricing?currency=usd` 的可选展示（先不做多币种切换，避免猜汇率）。

## 六、数据模型（现在就可以建）

```sql
-- 0002_billing.sql

-- 权益只有一个字段：到期时间戳。NULL 或 <= now 视为免费。
ALTER TABLE users ADD COLUMN pro_until INTEGER;

-- 申请记录（阶段一用）
CREATE TABLE IF NOT EXISTS pro_requests (
  id          TEXT PRIMARY KEY,
  user_id     TEXT NOT NULL,
  plan        TEXT NOT NULL,           -- month | year
  message     TEXT,
  status      TEXT NOT NULL,           -- pending | granted | rejected
  created_at  INTEGER NOT NULL
);

-- 订单
CREATE TABLE IF NOT EXISTS orders (
  id                TEXT PRIMARY KEY,
  user_id           TEXT NOT NULL,
  provider          TEXT NOT NULL,     -- manual | alipay | wechat | lemonsqueezy
  provider_order_id TEXT UNIQUE,       -- 平台订单号，幂等键
  plan              TEXT NOT NULL,     -- month | year
  amount_cents      INTEGER NOT NULL,  -- 下单时快照，不随定价调整变化
  currency          TEXT NOT NULL,     -- CNY | USD
  status            TEXT NOT NULL,     -- created | paid | refunded | failed
  paid_at           INTEGER,
  created_at        INTEGER NOT NULL,
  raw               TEXT               -- 回调原文，排查用
);

CREATE UNIQUE INDEX IF NOT EXISTS idx_orders_provider_order ON orders (provider_order_id);
CREATE INDEX IF NOT EXISTS idx_orders_user ON orders (user_id);
```

加时长逻辑（唯一需要小心的地方）：

```ts
// 续费叠加：从「现在」和「原到期时间」中取较晚者为基准
const base = Math.max(Date.now(), user.pro_until ?? 0);
const next = base + (plan === "year" ? 365 : 30) * 86400_000;
```

**不要**用 `now + 时长` 直接覆盖，否则用户在有效期内续费会丢掉剩余时间——这是最典型的投诉来源。

## 七、权限判定（阶段二再做，现在别动）

- 前端不要用客户端条件渲染藏数据（数据已在 JSON 里，等于没锁）。
- 正确做法：`apps/web` 加 `middleware.ts`，读 session cookie → 调 `GET /api/billing/me`（或用 JWT 里携带的 `proUntil` 避免每请求打 DB）→ 传给页面决定渲染范围。
- 榜单页的隐藏必须保留**前 N 条完整 HTML** 给搜索引擎，否则会被判 cloaking。这也是你决定「免费额度先不做」的好处：等想清楚 SEO 影响再动手。

## 八、合规、税务、发票

| 事项 | 说明 |
|---|---|
| 备案 | 国内支付通道的前置条件，先用阿里云/腾讯云完成网站备案 |
| 税种 | 个体工商户按「经营所得」缴税，小规模纳税人月销 ≤ 10 万免增值税 |
| 发票 | 用户多为个人，开票需求低，但需在定价页写明「可开票」并提供邮箱入口（已写） |
| 隐私 | 支付回调会带手机号/邮箱，只落库必要字段，不存卡信息（本来也不接触） |
| 退款 | 建议写进条款：7 天内未使用核心权益可退，按比例扣除已使用月份 |

## 十、风险清单

1. **备案被驳回或周期超预期** → 阶段一的人工开通就是兜底方案，不要因为支付没接上而推迟收费验证。
2. **支付宝签约要求网站内容与经营范围一致** → 备案时将网站描述写成「信息技术服务 / 数据服务」，不要写「AI 工具导航」这类模糊描述。
3. **年付折扣 57% 过深** → 会让月付变成纯锚点，也可能让用户怀疑原价虚高。如果后续月付转化率低于 10%，建议把月付调到 ¥29（年付 ¥99 即省 72%，文案需同步改），或直接砍掉月付只卖年付。
4. **定价页 CTA 指向 `/account` 会让未登录用户困惑** → 建议在 CTA 旁保留一句「开通前可先免费使用全部数据」，当前版本已在 FAQ 中说明。
5. **回调丢失** → 必须有主动查询兜底（用户点「我已完成支付」时反查平台订单状态），不能只依赖异步通知。

## 十一、建议你现在做的三件事

1. **今天**：把 ICP 备案启动（免费，但占日历时间，越早越好）。
2. **本周**：加 `pro_requests` 表和后台手动开通接口，把定价页 CTA 改成「申请开通」（登录后可见）。这不需要任何支付资质，一周内就能产生第一笔真实收入。
3. **有 20 个付费用户后**：个体户 + 支付宝直连，再补微信。国际卡等海外订单真的出现再说。
