1	月访问量	monthly_visits	网站每月总访问次数
2	月访问量增长率	monthly_visits_growth	最近一个月相较上一个月的访问量变化百分比
3	自然搜索流量	organic_search_visits	每月通过自然搜索带来的访问次数
4	直接访问流量	direct_visits	每月通过直接访问等直接流量渠道产生的访问次数
5	引荐流量	referral_visits	每月从其他网站链接进入的访问次数


针对你列出的 8 个指标，结论是：**Apify 的 Similarweb 系 Actor 可以覆盖全部 8 项，而 DataForSEO 主要能覆盖第 3 项（自然搜索流量），且口径不同（ETV 而非访问次数）**。建议以 Apify 作为这 8 个指标的统一数据源，DataForSEO 仅用于自然搜索流量的交叉参考或关键词深挖。

以下是逐指标的完整方案。推荐使用 Apify 上的 `lergassy/similarweb-traffic-scraper`，因为它的输出模式对“访问量 / 互动 / 流量来源拆分”的字段定义最清晰、覆盖最直接，单价为 **$2.80 / 1,000 域名**，你的 $5 体验金足以覆盖约 1,700+ 个域名的单次全字段查询。

## 指标 1：月访问量（`monthly_visits`）

**首选：Apify**

- **字段**：`monthlyVisits`
- **类型**：`integer`
- **含义**：快照月份内的总访问次数（桌面端 + 移动端网页）。
- **快照月份**：同级的 `snapshotMonth` 字段（`YYYY-MM`）标明数据对应的月份。

**调用示例**（同步获取数据集条目）：
```bash
curl -X POST "https://api.apify.com/v2/acts/lergassy~similarweb-traffic-scraper/run-sync-get-dataset-items?token=$APIFY_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"domains": ["example.com"]}'
```
响应中每个域名的条目会包含 `monthlyVisits` 字段。

**文档**：`https://apify.com/lergassy/similarweb-traffic-scraper/output-schema`

**DataForSEO 补充说明**：DataForSEO 的 `organic.etv` 和 `paid.etv` 是**搜索渠道**的估算流量，**不包含**直接访问、社交、引荐等非搜索渠道，因此**不应直接等同于 `monthly_visits`**。如果仅需自然搜索流量，见指标 3。


## 指标 2：月访问量增长率（`monthly_visits_growth`）

**首选：Apify**

- **字段**：`monthlyVisitsChange`
- **类型**：`number`
- **含义**：相对于上一个月的访问量变化，以**小数形式**表示。例如 `0.0955` 表示增长 **+9.55%**；负值表示下降。
- **历史序列**：`monthlyVisitsHistory` 返回最近 3 个月的 `[{month, visits}]` 数组，可用于自行计算更长时间窗口的增长率。

**文档**：同上，`https://apify.com/lergassy/similarweb-traffic-scraper/output-schema`

**DataForSEO 是否可用**：DataForSEO 的 Domain Rank Overview 不直接返回访问量增长率。`historical_rank_overview` 端点提供历史 ETV，但仅限**搜索渠道**，且需要额外调用并自行计算变化率，不是获取“全渠道访问量增长率”的合适工具。


## 指标 3：自然搜索流量（`organic_search_visits`）

### 方案 A：Apify（全渠道口径中的自然搜索份额）

- **字段路径**：`trafficSources` 数组中的 `source` 为 **`"Organic Search"`** （或类似命名）的元素，取其 `share` 字段。
- **结构示例**：
```json
"trafficSources": [
  {"source": "Direct", "rank": 1, "share": 0.35},
  {"source": "Organic Search", "rank": 2, "share": 0.40},
  {"source": "Referrals", "rank": 3, "share": 0.15},
  {"source": "Social", "rank": 4, "share": 0.10}
]
```
- **获取绝对访问次数**：用 `monthlyVisits × organicSearchShare` 估算。

**注意**：Similarweb 的公开页面可能对非顶级渠道的 `share` 返回 `null`，只保证 top channel 的份额可见。实际调用时需处理 `share` 为 `null` 的情况，或改用提供完整渠道拆分的 Actor。

### 方案 B：DataForSEO（搜索渠道的独立估算，适合交叉验证）

- **端点**：`/v3/dataforseo_labs/google/domain_rank_overview/live`
- **字段**：`metrics.organic.etv`
- **类型**：`float`
- **含义**：基于 CTR × 搜索量计算出的**估算月度自然搜索流量**。DataForSEO 文档明确将其定义为 “estimated organic monthly traffic to the domain”。
- **请求示例**：
```bash
curl -X POST "https://api.dataforseo.com/v3/dataforseo_labs/google/domain_rank_overview/live" \
  -u "$DFS_LOGIN:$DFS_PASSWORD" \
  -H "Content-Type: application/json" \
  --data '[{"target": "example.com", "limit": 1000}]'
```

**文档**：`https://docs.dataforseo.com/v3/dataforseo_labs/google/domain_rank_overview/live/`

**口径提醒**：Similarweb 的 `organic search share` 是**全渠道访问中的自然搜索占比**；DataForSEO 的 `organic.etv` 是**搜索渠道的独立流量估算**。两者可以作为方向性交叉验证，但数值不完全对等。


## 指标 4：直接访问流量（`direct_visits`）

**唯一实用来源：Apify**

- **字段路径**：`trafficSources` 中 `source` 为 **`"Direct"`** 的元素，取其 `share`。
- **绝对访问次数**：`monthlyVisits × directShare`。

DataForSEO **不提供**直接访问流量的估算，其 Labs API 仅覆盖 organic 和 paid 搜索渠道。


## 指标 5：引荐流量（`referral_visits`）

**唯一实用来源：Apify**

- **字段路径**：`trafficSources` 中 `source` 为 **`"Referrals"`** 的元素，取其 `share`。
- **绝对访问次数**：`monthlyVisits × referralShare`。
- **补充字段**：部分 Actor 还提供 `topReferringSites` 或 `referringSitesTotal`，可用于识别主要引荐来源域名。

DataForSEO 同样不覆盖引荐渠道。


## 指标 6：社交媒体流量（`social_visits`）

**唯一实用来源：Apify**

- **字段路径**：`trafficSources` 中 `source` 为 **`"Social"`** 的元素，取其 `share`。
- **绝对访问次数**：`monthlyVisits × socialShare`。
- **更细的社交拆分**：部分 Actor（如 Similarweb Pro Scraper）可进一步区分 `socialOrganicTraffic` 与 `socialPaidTraffic`，或在 `trafficSources` 中拆出社交子渠道。

**文档**：`https://apify.com/lergassy/similarweb-traffic-scraper/output-schema`（`trafficSources` 字段说明）；更细的社交拆分可参考 `https://apify.com/santamaria-automations/similarweb-scraper` 的 changelog。

DataForSEO 不覆盖社交媒体渠道。


## 指标 7：月页面浏览量（`monthly_pageviews`）

**首选：Apify（通过两个字段计算）**

Similarweb 系 Actor 通常**不直接返回** `monthly_pageviews` 作为一个独立字段，但可以通过两个已有字段精确计算：

- **公式**：`monthly_pageviews = monthlyVisits × pagesPerVisit`
- **`monthlyVisits`** ：整数，月总访问次数。
- **`pagesPerVisit`** ：数值，平均每次访问浏览的页面数。例如 `8.42` 表示每次访问平均浏览 8.42 个页面。

**计算示例**：若 `monthlyVisits = 2,500,000`，`pagesPerVisit = 3.2`，则 `monthly_pageviews = 8,000,000`。

**文档**：`https://apify.com/lergassy/similarweb-traffic-scraper/output-schema`（`pagesPerVisit` 字段定义）。

**备选**：部分 Actor（如 NanoScrape 系）可能直接输出 `monthly_pageviews` 或 `pageviews` 字段，选择时可在其输出模式中确认。

**DataForSEO 是否可用**：DataForSEO 的公开 Labs 端点**不提供**全渠道月页面浏览量。点击流数据中可能包含 page views 指标，但并非 Domain Rank Overview 的标准输出字段，不适合作为批量获取页面浏览量的方案。


## 指标 8：平均访问时长（`avg_visit_duration`）

**唯一实用来源：Apify**

- **字段**：`avgVisitDuration`（字符串，`HH:MM:SS` 格式，如 `"00:02:53"`）
- **秒数版本**：`avgVisitDurationSeconds`（整数，便于程序化处理）
- **类型**：`string` / `integer`
- **文档**：`https://apify.com/lergassy/similarweb-traffic-scraper/output-schema`

部分 Actor 将时长、跳出率、页均浏览数合并到 `engagement` 对象中，例如：
```json
"engagement": {
  "bounceRate": 0.405,
  "pagesPerVisit": 3.2,
  "avgVisitDuration": "00:02:53"
}
```
调用时以具体 Actor 的输出模式为准。

**DataForSEO 是否可用**：DataForSEO 的点击流数据理论上包含访问时长信息，但它**不是** Domain Rank Overview 或 Bulk Traffic Estimation 的标准输出字段，没有稳定、直接的 `avg_visit_duration` 字段可供批量调用。**不建议**用 DataForSEO 获取此项。

## 给 AI Agent 的编排建议

1. **先调 Apify，一次拿到 8 项中的 7 项（第 3 项也以份额形式拿到）** 。Agent 只需对目标域名调用一次 `run-sync-get-dataset-items`，响应中即包含 `monthlyVisits`、`monthlyVisitsChange`、`trafficSources`、`pagesPerVisit`、`avgVisitDurationSeconds`。在 Agent 内部做两次简单运算：`monthlyVisits × share`（得到各渠道绝对访问量），`monthlyVisits × pagesPerVisit`（得到月页面浏览量）。
2. **DataForSEO 仅在需要“自然搜索流量”的独立交叉验证时调用**。调用 `domain_rank_overview/live`，取 `metrics.organic.etv`。提醒 Agent：这个数字只代表搜索渠道，不要与 Apify 的 `monthlyVisits` 混算或相加。
3. **处理 `share` 为 `null` 的情况**：Similarweb 公开数据可能仅完整展示 top channel 的份额，其余渠道的 `share` 可能为 `null`。Agent 应具备回退逻辑：若目标渠道的 `share` 为 `null`，则将该指标标记为“不可得”，而不是用 0 填充，以免误导下游分析。
